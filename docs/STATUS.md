**本番実行を2回した**（欠陥を直す前と後）。採用するのは修正後の455トピック版（→ `docs/experiments.md` 7.）。

**1回目の結果を点検して、前処理に構造的な欠陥が見つかった。**

- `remove_game_names(all_games=True)` がロスター24本の名前を**単語に割って全721,799件から消していた**（48語）。その中に `magic` `fantasy` `online` `simulator` `civilization` `wild` `human` `split` といった内容語が多数含まれていた

```
全レビューから消す    2語以上のタイトルの並び + proper_nouns.txt の46語
自ゲームだけから消す  タイトルを割った単語（48語すべてが降格）
自動では消さない      1語のタイトル（Starfield / Predecessor）
```

修正の途中で**同じ誤りが自分の設計にも残っていた**。1語タイトルは「完全なタイトル」でもあるため全レビューから消える設計になっており、`predecessor`（総1,815回のうち1,108回が Silksong の「前作」の意味）を失うところだった。1語は人が `proper_nouns.txt` に書く形に変更。テスト6件追加・全56件 green。

## 未解決・保留中の問題

### トピック抽出

- **固有名詞リストの取りこぼしは残る**。`hornet` `jeff` `spiderman` `deadpool` といった**キャラクター名**は、いまの設計（2語以上のタイトル＋手動46語）が想定していないカテゴリ。ただし該当トピックは1ゲーム99%台なので、主軸パネルからは機械的に外れる
- **`configs/` を gitignore するかが未決定**（現在は追跡している）
- **中身の無いトピックが残る**。上位50のうち8個が賞賛/罵倒語のトピック（`best game` `peak` `alright, guess` 等）。固有名詞の除去では消えず、タグ語彙に寄せるまで残る
- **細かさとゲーム固有はトレードオフ**でデータ量では解けない（`docs/experiments.md` 7.）。ロスターかタグ語彙の側で扱う
- **Outlier率がゲームで2.5倍違う**。Outlierは需要として数えられないので、ゲームによって「声が届く率」が変わる
- **トピックの目標粒度（物差し）が未決定**。「次に作るゲームの企画を書くとして、どのくらいの粗さの情報があれば足りるか」を1回だけ決める必要がある

### データセットの偏り

- **Marvel Rivals が全体の19.7%**（142,497件）。発売スパイクなので、トピックの時系列がこの1本の launch に引きずられうる
- **Starfield の発売スパイクが土台の期間の頭にある**。**時系列の主軸パネルからは外す**方針（データは残すので分析時のフィルタで済む）
- **全24本では参加ゲーム数が16〜24本で変動する**。絶対数を使うのは土台13本のパネルに限る
- **ジャンル均衡は「本数」で担保し、量の偏りは点検で見る方針に確定**。量ベースの均衡に変えるのは「需要スコアは実数合算」の決定と矛盾するため採らない

### 需要スコアの構造的な限界

- **レビュー数 = プレイヤー数 × 書く傾向**。賛否が割れるゲームは1人あたりのレビュー率が高く、レビュー爆撃も混ざる
- **大作のリリース時期がトレンドを作る**。時系列の山が「需要の変化」ではなく「発売スケジュール」を映す可能性がある
- **需要の測定が供給に引きずられる**。人は「あるもの」について語り「無いもの」については語らないため、未充足需要は最も観測されにくい
- **`get_popular_games()` の生存バイアス**と**タグのHTMLスクレイピング依存**（`docs/experiments.md` 5.）
