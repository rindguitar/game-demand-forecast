### 2026-09-09: ゲーム単位の共起を出した。24本では組み合わせを語れない（Issue #42）

`src/nlp/topic_cooccurrence.py` と `scripts/nlp/build_topic_cooccurrence.py` を追加（`make cooccurrence`）。
粒度は #37 の結論に従いレベル300。**再学習なし・数分**。

素朴に「同じゲームに出るか」で数えると、時系列に乗る35単位のうち**21個が全24本に出る**ため
ほぼ全結合になり情報にならない。

**⚠️ 24本では組み合わせを語れない**

```
min_lift  1ゲームあたりの部品数  共起ペア数  最大同居ゲーム数
   ×2            12            3,024         3
   ×5             7              875         2
   ×12            4              258         1   ← 企画書の粗さ（3〜4部品）
   ×20            3              150         1
```

**企画書の粗さまで絞ると、2本以上で同居するペアが1つも無くなる。**
緩めれば共起は出るが最大3本止まりで、「このペアが無い = 未開拓」とは言えない。
「共起していない」の大半は**ゲームが足りない**のであって市場の空白ではない。

**レシピは実用になる**。ゲームごとの部品構成が読める形で出た。

```
DAVE THE DIVER       fish, sushi, restaurant, diving / relaxing / chill / cozy
Forza Horizon 5      mexico, racing, cars / steering wheel / graphics / realistic
```

×2で同居した上位ペアは5組が**ライブサービス系のまとまり**を指している
（`grind` × `cosmetics` × `mmorpg` × `community` × `matchmaking` × `toxic`）。
ロスターの中の構造としては読める。

**レビュー単位の共起は今のデータでは取れない**。BERTopic の transform は1レビューに
1トピックしか付けない。取るなら `approximate_distribution` で分布を出し直す必要がある。

### 2026-09-09: トピックの粒度を測る物差しを作り、粗い側を実測した（Issue #37）

`src/nlp/topic_granularity.py` と `scripts/nlp/compare_topic_granularity.py` を追加。

**再学習しないので数分で回る**（→ `docs/decisions.md` 2026-09-09）。

**物差し = 有効単位数**。3条件を全部満たすものだけを数える。

```
週あたり件数の中央値 ≥ 10          時系列に乗る
× top1_share < 0.5                1本のゲームの話ではない
× 分類が ①要素 / ②品質 / ③ビジネス  中身なし・固有名詞ではない
```

到達率だけを見ると粗くするほど単調に上がって山が無い（23.7% → 56.3%）。有効単位数には山がある。

**密度の物差しを1本化した**。`weekly_median` と `measure_panels` を `src/timeseries/weekly.py` の
`measure_topic_panels()` に集約し、`categorize_topics.py` と粒度比較の**両方が同じ関数を呼ぶ**形にした。

**マージと再学習を突き合わせた**（`min_topic_size` を 20 → 50 にして再学習・218トピック・25分）。
同じ218単位で並べると**マージのほうが有効単位が多い**ので、
粒度を探すために再学習を繰り返す必要はない（→ `docs/decisions.md` 2026-09-09）。

```

```

学習側は到達単位こそ多いが、`friends` が2単位に割れる重複や
`naked, chased, bricks, molested` のような塊が残る。マージ側は
`hunting, fish, sushi, animals`（18,233件）のように言及がまとまる。
※束内距離は束ねていないレベルでは構造的に0になるので、そのレベル同士の比較には使えない。

**⚠️ 副産物: `min_topic_size` を上げると Outlier が減った**（43.9% → 40.5%・**24,509件を回収**）。
粒度の目標とは別の軸なので Issue #39 で扱う。モデルは `models/topic_min50` に残してある。

**結論: 単一の目標粒度は決められない**（→ `docs/decisions.md` 2026-09-09）。**#37 はクローズ済み。**

```
レベル  要素の有効単位  束内距離の中央値  部品の純度
  455        6           0.000        融合なし。ただし企画に効く単位がゼロ
  300       12           0.201        融合は起きるが時系列には乗らない
  200       19           0.296        融合した束がパネルに乗る
```

決めた1文は**「企画の部品が融合した束が時系列に乗らない範囲で、いちばん粗くする」**。
現時点の材料では **embedding のレベル300前後**。個数ではなく規則で決めているので、
レベル300は規則の結果であって目標値ではない。

**⚠️ 融合は粒度の選び方では避けられない**。`building` と `platforming` は455では別トピックだが
**300の時点で既に1つの束**（1,261件・距離0.310）。マージ木の順序は MiniLM の埋め込みが
決めているので、両者が近いと見なされる限りどのレベルでも分かれない。
**直すなら埋め込みの側**（別モデル、あるいはSteamタグでの教師付け）。
それでも300を採るのは、300ではその束が**週10件に届かず時系列に乗らない**ため。
線は「融合が起きるか」ではなく**「融合した束が成果物に乗るか」**で引いた。

**⚠️ 部品の粒度では単独の時系列が引けない**。455で横断していて意味のある到達単位は14個あるが、
中身は条件と品質だけで**「どんなゲームを作るか」に効くものがゼロ**だった。
原因は粒度が細かすぎることではなく**部品1つあたりの言及量が足りない**こと。
ゲームは部品の掛け合わせで出来ているので、部品ごとに合算すると
「どの組み合わせが未充足か」が消える。粒度では解けないので **Issue #42** に切り出した。

### 2026-09-06: トピック抽出の本番実行と、前処理の欠陥の是正

**本番実行を2回した**（欠陥を直す前と後）。採用するのは修正後の455トピック版（→ `docs/experiments.md` 7.）。


### 到達率が32.1%で頭打ちになっている件（→ [#39](https://github.com/rindguitar/game-demand-forecast/issues/39)）

時系列に乗るのは全レビューの32.1%。残りは Outlier 43.9% と、束ねても週10件に届かない小さいトピック。**束ねる工程では解けなかった**（→ `docs/decisions.md` 2026-09-06）ので、上げるなら Outlier 側に手を入れることになる。

**⚠️ Outlier は「短くて中身のない」レビューではなかった**（2026-09-09に実測）。着手前にこの前提を持たないこと。

```
語数帯          Outlier率      Outlier全体に占める割合
  0〜5語        34.0%   ← 最も低い        3.8%
  5〜10語       37.4%                    19.4%
 10〜20語       41.1%                    23.6%
 20〜50語       47.1%                    25.9%
 50〜100語      50.8%                    13.7%
100語〜         53.5%   ← 最も高い       13.6%

語数の中央値   Outlier 22語  /  割当済 16語
```

**長いレビューほど Outlier になっている。**100語以上のレビューは半分以上（53.5%）が捨てられている。長いレビューは複数の話題を含むので、埋め込みがどのクラスタの中心からも遠くなり、HDBSCAN が外れ値と判定する——BERTopic の素直な挙動。

含意は2つ。**「短文だから仕方ない」という逃げ道は無く、減らす余地がある。** そして**捨てているのは情報量の多いレビューのほう**で、需要スコアは実数合算なのでこの偏りがそのまま成果物に乗る。「丁寧に書いた人の声ほど落ちる」という形になっている。
