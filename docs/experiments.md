## 1. 感情分析モデルの精度

### 現行の基準値（2026-08-31・新OODセット・15シード平均）

| モデル | OOD精度 | 備考 |
|---|---|---|
| DAPT版 | **86.85%** | ドメイン適応事前学習あり |
| vanilla | **86.09%** | なし |

- DAPTの効果は **+0.76pt**。シードごとの対戦は **12勝3敗**で、方向は安定している
- OOD = 学習に使っていない未知ゲームでの評価（Issue #21 で構築）

### 旧OODセットの値（2026-08-18以前・**混ぜないこと**）

| モデル | OOD精度 | in-domain |
|---|---|---|
| DAPT版 | 88.7% | 86.6% |
| vanilla | 87.9% | — |

`get_popular_games()` が評価スコア順を返すバグ（下記 5.）の影響で偏っていたセットの値。
売上上位プール版へ差し替えたため、**現行値と直接比較できない**。

差し替えで総合精度はほぼ不変だったが、誤りの質が変わった。

### 判明している弱点

- **擁護型ポジティブレビュー**（「叩かれてるけど自分は好き」「不満はあるが良作」といった混合感情）で、ポジ側の正解率が **4〜5pt低下**する。賛否が割れるゲームで顕著。Issue #19 と地続き

## 2. レビューの発生密度（Issue #31・2026-08-31・57ゲーム）

`scripts/benchmarks/timeseries_feasibility.py` で測定。

| 母集団 | 密度（中央値） |
|---|---|
| 累計1万件以上 | 8.37件/日 |
| 累計10万件以上 | 45.97件/日 |
| 実測最大 | 234件/日 |

- **英語フィルタ通過率は中央値 65%**。`query_summary` の件数から使える件数を見積もるときは要補正
- **`get_review_summary()` は言語フィルタを反映している**。`games.csv` の件数もポジ率も最初から英語のみ

### 中央値は5倍過小だった（2026-09-04に判明）

上の 8.37件/日 は57ゲームの**中央値**で、実際に収集する母集団（売上上位）では **208件/日・ゲーム**だった。
この誤りが「30本ないと密度が足りない」という前提を作っていたが、実測では**15本・週3,115件**（目標の3.6倍）で足りていた。

## 3. レビューのポジティブ率（自然比率）

| 対象 | ポジ率 |
|---|---|
| 学習7ゲーム合計 5,716,738件（全期間） | **88.8%** |
| 最高: Stardew Valley | 98.8% |
| 最低: GTA V | 83.7% |
| 時系列データセット 721,799件（直近3年） | 76.4%（期待値80.8%・乖離 −4.5pt） |

**50:50に均衡させた学習データは、ネガを実態の約4.5倍に水増ししていた**（`collect_balanced_reviews()`）。
このため、ネガ側にしか出ないトピック（crashes等）は件数を増やしても正しい比率にならない。

## 4. 年次季節性は検出できなかった（2026-08-31・8ゲーム×3年）

`seasonality_check.py` で測定。

- 2024 vs 2025 の**月別シェア相関 r = +0.36**。季節性と呼べる再現性は無い
- 11月に見えた山は **IdleOn の単発イベント**（通常月の4.3倍）だった。個別ゲームのイベントが全体の形を作っていた

**留保**: 完全な年が2つしか無い / 8ゲームでは個別イベントを打ち消しきれない / **週次の周期性は未測定**。

帰結: 「遡る期間は2年必要」という根拠が弱まり、期間の下限は「予測したい長さ × 3〜10」で決まることになった（→ 3年を採用）。

## 5. Steam API の実測で判明した挙動

- **`get_popular_games()` の `sort_by='Reviews_DESC'` はレビュー数順ではなく評価スコア順**だった（2026-08-31に発見・修正）。上位20本の累計レビュー中央値が 3,312件 → `globaltopsellers` で 79,866件に変わった
- **`get_popular_games()` は「いまの売上上位」を返す**ため、過去の断面には生存バイアスがかかる。2023年のデータは「2026年まで生き残ったゲームの2023年」しか見えない。母集団の取り方を変える手段が無いため制約として受け入れる
- **空ページを返すことがある**。連続アクセスに対しエラーではなく空ページを返し、それを「レビュー終端」と解釈すると収集が黙って切れる（→ Wiki [Silent Truncation](https://github.com/rindguitar/game-demand-forecast/wiki/Silent-Truncation)）
- **`appdetails` の `data` がリストで返るケースがある**（Eternal Return・1049590）。`get_game_genres()` がこれで落ちていた
- 販売本数・DL数は取得不可。同接は現在値のみ
- タグは `appdetails` に含まれず、**ストアページのHTMLスクレイピング**で取っている

**横断トピックはむしろ強くなった**。週10件以上の言及量に占める複数ゲーム（top1<50%）の割合は **40.2% → 43.8%**。

### トピックの4分類（2026-09-06・455トピック）

- **中身なしが、時系列に乗る言及量の19.9%を占めていた**（45,172 / 226,755件）。`best game` `goty` `hours` `pass time` `good good` など。3分類のままだと①の受け皿に流れ込んで需要スコアを水増しする

### 試走3回の比較（2026-09-05）

| | 9,257学習 | +固有名詞除去 | 42,113学習 |
|---|---|---|---|
| 対象件数 | 20,000 | 20,000 | 100,000 |
| トピック数 | 65 | 69 | 228 |

割当 100,000件 → 157秒（件数に比例）

## 9. 旧データ（`reviews_10000.csv`）が時系列に使えない理由

2026-08-18に実測。Phase 7 で別途収集する判断（`docs/decisions.md`）の根拠。

- **密度不足**: 5,605件 ÷ 86トピック ÷ 549日 = **1トピック1日あたり0.12件**。表のほとんどが0になる
- **自然比率の欠如**: `collect_balanced_reviews()` がPos/Negを50:50に強制しているため、ネガ側にしか出ないトピックが水増しされている。**件数を増やしても直らない**
- **期間がバラバラ**: 件数固定で集めたため、CS2は3日分・Stardew Valleyは190日分と時間軸が揃っていない

## 10. 一律圧縮は誤りだった（2026-08-31）

確定仕様（30本・週次）で週あたり998件（トピック付き）。

```
トピック86個のまま → 平均 11.6件/週  足りる
ただし実際の分布は偏る（最大6.1% / 中央値0.9% / 最小0.4%）
  → 中央値のトピックは 8.6件/週（不足）
  → 最小のトピックは   3.6件/週（大幅に不足）
```

**一律に15〜20個へ圧縮する必要はない。密度が足りないのは小さいトピックだけ。**
それまで「15〜20個に束ねる」と繰り返していたのは平均だけを見た誤りだった。
